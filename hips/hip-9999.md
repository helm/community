## Abstract

HIP-0011, "CRD Handling in Helm 3", introduces `crds/` for managing
Custom Resource Definitions (CRDs). It also states:

> NOTE: There is no requirement that CRDs can only be placed in the `crds/` directory. They can be put along side other resources in the `templates/` directory. This was an intentional design choice to preserve backward compatibility.

This backward compatibility is very prejudicial and should have been removed in Helm 4,
which was already no longer accountable for backward compatibility with Helm 2. I propose
removing this backward compatibility in Helm 5.

## Motivation

Kubernetes ecosystem components, like Treafik, Calico and many others, abuse this legacy
behavior and ship broken charts that fail to install due to the huge size of CRDs trying
to land in the Helm storage Secret. Kubernetes rejects persisting the Helm storage Secret
with:

`Secret "sh.helm.release.v1.traefik-crds.v1": data: Too long`

The ecosystem components tell users to `helm template` these charts, which is a workaround
that does not respect Helm's lifecycle features. Helm controllers, like Flux helm-controller,
that are built entirely to honor Helm's lifecycle features, and therefore choose not to support
workarounds like `helm template`, cannot install those charts and error out with:

`Helm install failed for release flux-system/traefik-crds with chart traefik-crds@1.18.0: Secret "sh.helm.release.v1.traefik-crds.v1": data: Too long`

## Rationale

By removing the legacy support for CRDs under `templates/`:

- Helm prevents ecosystem components from shipping charts that cannot be installed due to
  CRDs exceeding the size limit of the Helm storage Secret.
- Helm prevents abusive charts that manage CRD lifecycle, bypassing Helm's current design:
  CRD lifecycle management is not officially supported. Helm 5 should enforce that.

The replacement, `crds/`, already exists and is GA since Helm 3.

## Specification

Error loud and clear when CRDs are found under `templates/`, in the following commands:

- `helm install`
- `helm upgrade`
- `helm template`
- `helm package`
- `helm lint`

## Backwards compatibility

No backward compatibility. The HIP goal is specifically to remove
backward compatibility with Helm 2 in Helm 5 for a specific feature.
